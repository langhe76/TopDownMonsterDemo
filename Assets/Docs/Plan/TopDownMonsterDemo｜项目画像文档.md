## 1. 项目概述

### 1.1 项目简介

> 俯视角（Top‑Down）小型战斗演示 Demo，Unity 2022 LTS。 实现玩家角色与怪物 AI 战斗交互；核心聚焦**代码架构设计、对象复用性能优化**，用来体现 Unity 客户端工程开发能力。 重点：**不是做独立游戏，是技术演示项目**。玩法轻量化，技术模块深度优先，拒绝堆砌无关功能。

### 1.2 游戏业务简述（实际运行看到的效果）

1. 场景：简单平面地面场景，少量怪物生成点；无复杂关卡、无剧情。
2. 玩家：可键盘控制移动；拥有待机、跑动、攻击、受击四种行为状态；可以发射子弹攻击怪物，受到怪物攻击会进入受击。
3. 怪物 AI：复用同一套状态机框架，具备巡逻、追击、攻击状态。怪物发现玩家会追击，距离过远丢失目标回归巡逻；靠近玩家发起攻击。
4. 战斗表现：大量子弹、怪物实体频繁生成销毁；用对象池解决 Instantiate/Destroy 带来的 GC 抖动。

## 2. 核心技术亮点（简历 + 面试口述核心，重中之重）

> 面试讲项目优先讲下面这些点，而不是讲 “我做了个打怪游戏”

1. 通用泛型 FSM 有限状态机（纯 C# 逻辑层，不依赖 Animator）
   - 实现`StateBase<TState>`状态基类 + `StateMachine<TState>`管理器；一套框架同时服务玩家角色、怪物 AI 两套业务。
   - 状态单一职责，每个状态独立类；规避传统 Update 中大段 if‑else 面条代码。
   - 内置防护逻辑：禁止重复切换相同状态，防止重复执行 Enter，规避状态堆叠 bug。
2. 通用对象池 ObjectPool，解决高频生成销毁 GC 问题
   - 支持子弹、怪物、特效多种物体复用；支持自动扩容、回收、清空。
   - 保留 Profiler 原始对比数据：原生 Instantiate/Destroy VS 对象池方案的 GC 分配、帧耗时对比，有量化凭证。
3. 工程与版本管理规范
   - 合理项目目录分层：Framework 通用框架层 / Game 业务逻辑层 / Docs 文档凭证层。
   - Git 规范配置，正确处理`.meta`，语义化 commit；所有技术笔记、Profiler 截图随仓库归档，可在线查阅。

## 3. 明确：本 Demo 刻意不做的内容（很重要，防止无限膨胀）

> 写进文档，时刻提醒自己；面试也可以主动说明，体现你的取舍思维。

- ❌ 不做复杂美术资源、精致 UI 界面、主菜单、存档系统
- ❌ 不做复杂 Shader、后处理、高级渲染（属于加分项，本短期阶段不纳入）
- ❌ 不做完整游戏流程、多关卡、剧情、音效系统
- ❌ 不使用 Animator 状态机做业务逻辑；角色行为完全使用手写 FSM，Animator 仅播放动画表现
- ❌ 不接入热更、Addressable 资源框架（属于中期目标内容，留给后续迭代）

> 取舍逻辑：校招作品集，优先把**2 个核心模块做深、有数据、有文档**，远胜于一堆浅尝辄止的功能。
